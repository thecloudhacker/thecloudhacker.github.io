GitLab Critical Flaw

22nd October 2026

GitLab have released fixes for a critical flaw (CVSS 10.0 - CVE-2026-110264) that lets an attacker run code on a self-managed server without logging in, affecting every version of the software from 7.0 (released in 2014) onwards.

GitLab said that, under certain conditions, it could allow an unauthenticated user to run arbitrary code on the server due to an integer overflow during the compilation of a specially crafted regular expression. They do not mention what those conditions are, however you can be sure attackers are using AI to brute force those conditions right now.

Only self-managed installations need to act. GitLab.com already runs the fixed version, and GitLab Dedicated tenants on the internal releases 19.3.5-internal0 and 19.4.2-internal0 or later already have the fix

The flaw originates in the regular-expression compiler (Ruby's built-in engine, called Onigmo), which GitLab ships inside its own packages and patches in its own builds. A weakness in that engine has been present since 2014.
